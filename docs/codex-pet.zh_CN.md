## 首次 Wi-Fi 配置

1. 经授权刷机后开机。没有已保存网络时启动 WPA2 保护的 `CodexPet-xxxx` 热点，
   屏幕显示大号 Wi-Fi 二维码，以及供手动连接的热点名称和临时密码。
2. 用手机相机或 Wi-Fi 扫码入口扫描，确认加入设备热点。手机提示无互联网时仍需
   保持连接。兼容的手机会自动打开配网页；如果没有弹出，单击设备 OK 切换为网页
   二维码，**先加入设备热点后**扫码打开 `http://192.168.4.1/`，也可在浏览器手动
   输入该地址。再次单击 OK 返回 Wi-Fi 二维码。手机型号兼容性仍需设备验收。
3. 从附近网络列表选择正常使用的 2.4 GHz Wi-Fi，或手动输入隐藏网络名称，再填写
   密码。网页提供刷新列表和显示密码。SSID 为 1–32 个 UTF-8 字节；开放网络密码
   可为空，WPA 网络密码为 8–63 字节。连接期间配置热点保持开启，网页显示连接状态。
   密码错误、网络不可用或连接超时 25 秒时保留配网页供重试，不替换之前保存的凭据。
   获取 IP 后将名称和密码作为一个 NVS 数据块保存，留出 8 秒显示成功状态后重启。
   私下保存页面上的电脑配对密钥，然后重新加入正常网络。设备重启连接后显示 IPv4
   地址。二维码传递设备临时热点凭据，不能读取手机已保存的家庭 Wi-Fi 密码。
4. 运行电脑桥接配对，通过隐藏输入提示填写密钥：

```bash
python3 tools/codex_pet/bridge.py pair --host <device-IP>
```

配置保存在权限受限的 `~/.config/ai-passport/codex-pet.json`。设备地址变化时用新地址
和原密钥重新配对。在宠物页长按下键重新配置、查看密钥或更换网络。配置网页仅在热点模式
提供，正常连接时不开放。正常运行时，已保存网络不可用会每 5 秒尝试重连；在宠物页长按
下键重新进入配置。配网门户通过本地 DNS 响应、HTTP 探测重定向和 DHCP 门户 URI
提示手机；该 URI 返回门户 JSON 响应，不拦截 HTTPS。各手机行为不同，因此保留网页
二维码和手动地址。扫描、DNS、连接验证和保存均在应用工作任务执行，不分配蓝牙
协议栈或额外 DNS 任务。

## 连接 Codex 生命周期事件

桥接使用[官方 Codex Hooks](https://learn.chatgpt.com/docs/hooks)，状态同步无需
模型 API Key、额外推理或云服务。安装处理器并运行：

```bash
python3 tools/codex_pet/bridge.py install-hooks
python3 tools/codex_pet/bridge.py run
```

安装会保留其他 Hook、备份旧文件，处理会话开始/结束、用户提示、工具开始/结束、
审批、回合停止和中断。**在 Codex 中检查并信任新 Hook；未信任的 Hook 会跳过。**
按需重新加载会话/配置，再启动新回合。桥接无法重建它启动前的聊天，需先观察完整回合。

生命周期事件仅将类型、哈希后的 Session/回合/工具 ID 和输入等待标志发送至本机
UDP 19283，不传提示词、工具结果和助手消息。交互模式下，PermissionRequest Hook
还会将其 Session ID、工具名和参数发送至有界的**仅本机** TCP 19286 审批代理，
以便检查真实操作。桥接不记录或保存这些内容。决定仅适用于那条待审批请求，中断、
过期、重复 Confirm 不会批准其他请求。Hook 最多等待 115 秒，然后返回 `{}`，
由 Codex 继续正常桌面审批。桥接不在时快速返回。安装的 PermissionRequest 超时为
120 秒，其他 Hook 为 1 秒。见 [Codex 支持的 Hook 决定](https://learn.chatgpt.com/docs/hooks)。

状态每秒通过 UDP 19284 发送，使用 HMAC-SHA256 认证，密钥不传输。递增计数器
拒绝本次设备启动内的重复/乱序帧。状态认证但不加密。交互模式显示所选 Session
观察到的 Hook 状态；尚未观察到事件时为未知。停止不等于任务成功。丢失的事件不重放；
崩溃后缺少结束事件时，30 分钟未收到 Hook 后显示未知。

控制、音频和文字画面通过 TCP 19285 传输。双方用配对密钥进行 HMAC 挑战认证，
随机客户端/服务器 nonce 为每条连接、每个方向派生不同的 AES-256-GCM 密钥。
计数器与认证记录拒绝篡改/重放。断开后丢弃未完成录音；桥接器草稿在认证重连后恢复。电脑 IP 仅来自
认证成功的状态发送者。防火墙需允许本地 UDP/TCP；访客网络客户端隔离和超出
Wi-Fi 范围会断开。电脑桥接必须保持运行。

使用其官方模型下载器下载多语言 GGML 模型；仅英文的 `.en` 模型不支持普通话。
默认模型路径为 `~/.cache/ai-passport/ggml-base.bin`，其他本地模型用 `--model` 指定。

```bash
python3 tools/codex_pet/bridge.py install-hooks
python3 tools/codex_pet/bridge.py run --interactive --model /absolute/path/to/ggml-base.bin
```

在 Codex 信任并重新加载更新后的 Hook，不自动修改信任存储来启用审批。电脑本地
转写，无需模型 API Key，不上传录音。录音格式为 16 kHz、16-bit、单声道，最多
30 秒。每段使用 Whisper 自动识别语言，新识别文字在预览前默认通过
[OpenCC](https://github.com/yichen0831/opencc-python) 统一为简体，避免多段输入
简繁交替。已有桌面文字和会话元数据不转换，英文和数字保持原样。每段新录音
缺少句末标点时补句号（包含中文用 `。`，纯英文用 `.`）；已有句号、问号、
感叹号和省略号保留，避免重复添加。可用
`--chinese-script traditional` 输出繁体，或用 `--chinese-script keep` 保留多语言
识别结果的中文简繁字形。安装桥接依赖即可获取 `opencc-python-reimplemented`；转换在本地
完成，只统一字形，不纠正识别错词。
默认桥接器启动自己管理的 `whisper-server`，仅监听 `127.0.0.1`，在设备录音前
完成现有模型加载。后续录音复用模型，请求间的文本上下文为零；中英文及混合语音
仍自动识别语言。WAV 请求保存在内存，桥接器退出时停止子进程，其静态文件根目录
使用私有空目录。未安装 `whisper-server` 时 `auto` 使用 CLI；可用
`--asr-backend cli` 明确恢复每段重新加载，或 `server` 强制使用常驻模型。
工作进程失败后停止，下次录音可重新启动。CLI 临时 WAV/转写文件权限受限，
转换后删除；进程崩溃可能留下临时文件，需要手动清理。
现有聊天中，松开 OK 后转写并填入所选电脑输入框，卡片随即回到会话列表。
转写文字不在卡片上显示或保存。列表中短按 OK 发送电脑输入框当前内容，包括
在电脑上编辑过的文字；即使没有录过语音也可以发送。电脑输入为空或已清空时
不发送，不回退到桥接器缓存的语音。录音和填入不会启动回合；只有审批确认
需要先查看请求的每一页。

连续录音在桥接器内存中累积，直到发送或离开所选聊天。每次填入用完整累积
语音替换电脑输入，不按光标插入，也不合并电脑编辑。填入后最多等待 2.5 秒，
等待保存确认。保存延迟时保留待确认状态并返回列表，不再因为草稿尚未落盘，
就把已接受的桌面填入路由报成失败。路由启动失败时才显示可关闭的错误提示，
不会自动发送；未确认填入时请检查电脑实际输入。补充转写失败或中断时保留
此前语音和电脑文字。等待、自动返回
宠物和交互连接认证重连都会保留桥接草稿；重启桥接器后丢失。选择记录文件不
保存转写文字或音频。已准备的新聊天首条语音也只保存在桥接器内存，卡片只
显示通用的待发送提示，不显示转写原文。

每次确认发送现有聊天时，先等待 0.8 秒，让最近的电脑编辑保存，再读取所选
聊天的持久化输入。未确认的填入必须先保存为预期语音或变化后的电脑文字，
不能在填入待确认时发送此前旧文字。清空输入时不发送。找到桌面执行实例后
再次核对当前内容。如果确认期间内容改变，本次不发送。支持普通字符串和仅含
段落、文字、换行的文档；附件、提及和格式化输入需要在电脑提交。IPC 发送后
电脑输入可能仍保留，由用户在电脑处理。提交前消费画面令牌，同一事件重复
到达不会重试结果不确定的发送；结果未知时先在电脑检查所选聊天。

审批中长按 OK 也可录音并填入电脑输入，随后恢复同一请求、页码及已查看进度，
不会批准请求或发送消息。恢复后短按 OK 仍只确认该请求，全部页显示过后才能
批准。实际填入、当前输入发送和审批仍需桌面与设备验收。

对于现有聊天，桌面适配器使用本机聊天执行实例的协调 IPC，不另启第二个执行实例。
仅在确认新聊天首条消息后，才启动新的
`codex exec --json --cd <saved-project-folder> -` 进程；语音通过 stdin 传入，
不用 Shell，也不记录提示词。使用现有 CLI 认证与配置，保留正常的沙箱和 Hook
信任规则，不覆盖模型或权限。CLI 设置可能与桌面输入页不同；桥接器不额外授予
编辑或审批权限。参考 [OpenAI 非交互 CLI 说明](https://developers.openai.com/codex/noninteractive)。
可用 `CODEX_CLI_PATH` 指定已安装的可执行文件；macOS 会在 PATH 命令之前检查
匹配的已安装 Codex 应用包。CLI 损坏时会停止准备，不修改安装或用户配置。

桥接器从 JSON 事件跟踪新会话 ID，读取并丢弃其余输出，不保存原文。仅在 CLI
退出后才在桌面打开聊天，列表发现后选中该会话。桥接器的录音、输入填入和提交
不能接管仍由 CLI 执行的聊天；同一时间只运行一个新聊天首轮。首轮结束前请勿
手动打开该聊天；保持桥接器运行，使用 Ctrl+C 正常停止。关闭已提交提示仅改变
导航，不取消已提交任务。首轮失败或结果不确定时提示在电脑检查，绝不自动重试。
桥接器异常终止以及手动桌面接管仍需验收测试。

适配器读取全部未归档
主聊天的元数据，不限制最近会话数量，也不要求聊天已加载到桌面。后台刷新会在
聊天创建、归档或移动后更新列表。项目归属通过当前本地主机的迁移记录解析旧 ID，
没有项目 ID 的 CLI 聊天还会按数据库中保存的根目录匹配。归档聊天、子代理以及
仍由桥接器执行的首轮会被排除。录音和输入框填入不要求聊天已有桌面执行实例；
设备明确提交时仍使用现有桌面执行实例，若聊天尚未加载，请先在电脑打开。该集成依赖版本，当前依据本机 0.160.0 CLI / 2026 年
10 月桌面代码验证；后续 IPC/数据库变化需要重新验证。不读取私人认证数据库或账户令牌。

初版支持语音追加消息和**工具权限**允许/拒绝，不回答任意多选问题、MCP elicitation
或登录对话框。忙碌/已关闭聊天可能拒绝消息；发送结果未知时提示在该聊天检查。
真实语音发送和审批执行是设备验收项目，不能从模拟测试推断通过。

无需设备检查桥接：

```bash
python3 tools/codex_pet/bridge.py run --dry-run
```

可选 USB 模式需要 pyserial 和明确选择的设备端口：

```bash
python3 tools/codex_pet/bridge.py run --port /dev/cu.usbmodemDEVICE
```

不能打开任意端口，也不能因为发现连接就刷机。
